以太网 - CSMA 碰撞检测实测：从单帧触发到 Burst 模式的全链路验证

前置阅读：本文是《多节点网络的冲突处理算法——从 ALOHA 到 PLCA》的姊妹篇。建议先阅读该文了解 CSMA/CD → CSMA/CA → PLCA 的演进脉络，本文聚焦于 CSMA/CD 碰撞检测在 10BASE-T1S 硬件上的实测验证方案。

实验环境：两块 Arduino UNO R4 Minima + LAN8650 MAC-PHY，10BASE-T1S 总线（双线），固件 fpga-pingpong.ino，实测日志 collision-test-*.log。

一、碰撞与退避的基本概念

1.1 CSMA/CD 三步曲

IEEE 802.3 定义的经典 CSMA/CD（Carrier Sense Multiple Access with Collision Detection）协议行为如下：

flowchart TD
    A["① Carrier Sense<br/>监听信道是否空闲"] --> B{信道空闲?}
    B -- 是 --> C["② 立即发送<br/>同时监听 MDI"]
    B -- 否 --> D["等待总线空闲"]
    D --> B
    C --> E{检测到碰撞?}
    E -- 否 --> F["✅ 发送成功"]
    E -- 是 --> G["③ Jam Signal<br/>发送冲突信号"]
    G --> H["Backoff 退避<br/>随机等待后重传"]
    H --> A

三步缺一不可：

  • Carrier Sense：先听后发，避免”可避免的”冲突
  • Collision Detection：边发边听，发现碰撞立即停止
  • Backoff：随机等待，避免二次冲突

1.2 碰撞窗口与 slot time

碰撞能被检测到的前提是：信号在物理上还没传完整个网段。

sequenceDiagram
    participant NA as 节点 A
    participant NB as 节点 B
    participant MDI as MDI 总线

    NA->>MDI: 发送 bit 0 @ t=0
    Note over MDI: 信号以 ~2×10⁸ m/s 传播
    MDI->>NB: 信号传输中... (延迟 τ)
    NB->>NB: 节点 B 监听: 空闲!
    NB->>MDI: 节点 B 也发! bit 0 @ t≈τ
    MDI->>MDI: ⚡ 两信号在总线上碰撞
    MDI-->>NB: 碰撞信号回传 @ t≈2τ
    NB->>NB: 节点 B 检测到碰撞 → Jam + Stop
    MDI-->>NA: 碰撞信号 @ t≈2τ
    NA->>NA: 节点 A 检测到碰撞 → Jam + Stop

    Note over NA,NB: 若 2τ > 帧传输时间 → 碰撞无法被检测到！

IEEE 802.3 Clause 147 规定 slot time = 51.2μs（512 bit times @ 10Mbps）。这是以太网最小帧长 64 字节的物理依据——确保在最坏传播延迟下，碰撞信号能在发送完成前返回。

1.3 Backoff 随机退避

碰撞后，节点在 2^k × slot time 内随机等待（k = min(重传次数, 10)）：

重传次数 k 窗口大小
1 0 ~ 51.2μs
2 0 ~ 102.4μs
3 0 ~ 204.8μs
… …
10+ 0 ~ 26.2ms

10BASE-T1S 的特殊性：单段距离 ≤ 25m，往返传播延迟 < 0.25μs，远小于 51.2μs slot time。物理上碰撞窗口富余，但 CSMA/CD 退避算法与标准以太网相同。

1.4 PHY 层碰撞检测寄存器（LAN8650）

LAN8650 PHY 芯片提供两个碰撞检测寄存器，通过 TC6 SPI 接口访问：

graph LR
    subgraph PHY["LAN8650 PHY 内部"]
        CD1["STS1 寄存器\n0x00040018\nbit10 = TXCOL\n(RC Latch)"]
        CD2["T1SPCSDIAG2 寄存器\n0x000208F6\nbits15:0 = CORTXCNT\n(RC, 饱和 0xFFFF)"]
    end

    subgraph MCU["Arduino (MCU)"]
        TC6["TC6 SPI 控制器"]
        READ["readPhyRegSync()\n同步读函数"]
    end

    READ --> TC6
    TC6 -->|"SPI Read"| CD1
    TC6 -->|"SPI Read"| CD2

    CD1 -->|"TXCOL latch\n碰撞事件标志"| R1["✅ 主碰撞指标"]
    CD2 -->|"CORTXCNT 增量\nMDI 损坏计数"| R2["✅ 辅助碰撞指标"]

两个指标的含义：

寄存器 含义 角色
STS1.TXCOL (bit 10) “PHY detects collision while transmitting” 时置位 辅助（PLCA/CSMA 模式均可能触发）
T1SPCSDIAG2.CORTXCNT (bits 15:0) 每次”本地发起的 TX 导致 MDI 信号损坏”的次数 主指标（PHY PCS 层，模式无关）

datasheet §7.2.5 原文：“When the PHY detects a collision while transmitting the Transmit Collision Status (TXCOL) bit is set”
datasheet §11.3.4 原文：“Number of times a locally initiated transmission resulted in a corrupted signal at the MDI”

二、碰撞触发方案架构

2.1 核心挑战：如何在实验室里可靠触发碰撞？

CSMA/CD 的设计目标就是让碰撞极少发生。两个节点同时发帧的概率本身极低。用手按按钮”同时”触发？人类反应时间 ~200ms，远大于 51.2μs slot time，根本不可能同步。

解决方案：GPIO 边沿触发 + 软件 burst 队列

flowchart TD
    subgraph Hardware["硬件连接"]
        BT["按钮\n(常开)"]
        D3N0["Arduino Node0\nD3 (P104)"]
        D3N1["Arduino Node1\nD3 (P104)"]
        BUS["10BASE-T1S 总线\n(双线 + GND)"]
    end

    BT -->|"按下 → 拉高"| D3N0
    D3N0 -->|"杜邦线直连"| D3N1

    subgraph Node0["Node0 ISR"]
        ISR0["collTrigISR()\ng_collTrigPending=true\ng_collTrigUs=micros()"]
    end

    subgraph Node1["Node1 ISR"]
        ISR1["collTrigISR()\ng_collTrigPending=true\ng_collTrigUs=micros()"]
    end

    D3N0 --> ISR0
    D3N1 --> ISR1

    ISR0 -->|"loop 检测 flag"| BM0["burst 状态机"]
    ISR1 -->|"loop 检测 flag"| BM1["burst 状态机"]

    BM0 -->|"100 帧 burst\n500us/帧"| TX0["sendCollTestFrame()"]
    BM1 -->|"100 帧 burst\n500us/帧"| TX1["sendCollTestFrame()"]

    TX0 --> BUS
    TX1 --> BUS

为什么杜邦线可以做到 <1μs 同步？

  • 按钮按下 → D3 从 LOW 变 HIGH → 两板外部中断同时响应
  • 杜邦线是纯电路连接，传播延迟 < 1ns，远小于 1μs
  • 两板的 micros() 差值即为真实的硬件触发时间差

2.2 三种触发模式对比

flowchart LR
    subgraph Modes["碰撞触发模式"]
        M1["① 单次 MAC 触发\nD3 下降沿 → 发 1 帧"]
        M2["② Burst MAC 触发\nD3 下降沿 → 发 100 帧\n间隔 500μs"]
        M3["③ PLCA 同 ID 触发\n两板均 NodeID=0\nPLCA → 强制同 TO"]
    end

    subgraph Results["PHY 层观测结果"]
        R1["❌ 永远无 collision\n单 node: 880us wait 常量\n双 node: carrier sense 避免\n结论: 测不到 wire-level"]
        R2["⚠️ 观测到 carrier sense\n双 node: 52ms 周期性长 wait\n单 node: 无\n结论: backoff 正常 ✓\n但仍无 wire collision ✗"]
        R3["✅ 必产生 collision\nwait ≈ 15μs (无 CSMA)\nTXCOL=1, CORTXCNT 自增\n结论: 确定性验证 ✓"]
    end

    M1 --> R1
    M2 --> R2
    M3 --> R3

    style R1 fill:#ffcccc
    style R2 fill:#fff3cc
    style R3 fill:#ccffcc
模式 代码配置 触发方式 物理结果 典型 wait
① 单次 MAC PLCA_NODE_COUNT=1 D3 触发 → 发 1 帧 永远无 collision 单 node: ~880μs 常量
② Burst MAC PLCA_NODE_COUNT=1 D3 触发 → 发 100 帧 无 wire collision（carrier sense 规避） 双 node: 880μs ~ 52ms 周期波动
③ PLCA 同 ID PLCA_NODE_COUNT=8, NodeID=0 同上 必 collision ~15μs 极短（无 CSMA 推迟）

三、实测对比：单 node vs 双 node Burst

3.1 单 node 对照组（无竞争者）

文件：collision-test-singlenode.log（Node0 独自挂在总线上）

关键观察：所有 100 帧 wait 都在 880~887μs（= 固定 PHY settle delay + 4× register read），没有任何 ms 级等待。这证明总线永远空闲，carrier sense 永远返回 idle。

3.2 双 node 实验组（存在竞争）

文件：collision-test-node0.log（Node0 + Node1 同时在总线上）

关键观察：周期性出现 52ms 长 wait，每 17~18 帧出现一次，其余帧维持 880μs。

3.3 量化对比

指标 单 node（对照） 双 node（实验） 差异 含义
wait 最小值 880μs 880μs 相同 PHY settle delay 常量
wait 最大值 887μs 52,600μs 59× 双 node 出现总线占用等待
wait 平均值 883μs 1,909μs 2.2× 双 node 竞争拖慢整体
ms 级 wait 帧数 0/100 5/100 全部 周期性 52ms 出现
Burst 总时长 ~90ms 656ms 7.3× 总线竞争拉长整体
TXCOL=1 帧数 0 0 — 两节点 MDI TX 永不同步
CORTXCNT delta 0 0 — carrier sense 成功规避了碰撞

3.4 52ms 长 wait 的物理来源

52ms ≈ 对方连续发了约 50 帧 × 1ms/帧。当 Node0 本轮 ready 时，Node1 可能正在 burst 中段——carrier sense 一直返回 busy，Node0 PHY 推迟到对方 burst 间隙才发。由于两板每帧的 ISR 延迟独立随机，同步触发后每帧的实际发送时刻逐渐漂移，约 17 帧后 Node1 重新占据了总线（等效”碰撞退避”）。

这就是 CSMA/CD 设计的预期行为：carrier sense 把后启动的节点推迟到总线空闲，双方 MDI TX 永远不会重叠。

五、PLCA 同 ID 强制碰撞的原理与操作

5.1 为什么 Burst 仍然没有 wire-level collision？

根本原因：CSMA/CD 的 carrier sense 机制主动避免了碰撞发生。

两节点的 MDI TX 时间差始终 > IFG (9.6μs)，远大于 slot time (51.2μs)——后启动的节点一定会在 preamble 阶段就听到 carrier 并推迟。PHY 永远只看到一个 driver → 永远不会报告 collision。

5.2 PLCA 如何绕过 carrier sense

PLCA（Physical Layer Collision Avoidance）用 BEACON + TO（Transmit Opportunity） 替代 carrier sense：

5.5 已知风险

风险 说明 对策
BEACON 冲突 两节点都发 BEACON → MDI collision → 一方丢失 coordinator 身份 等待自动恢复（通常 < 5s）
同步建立慢 PLCA 同步需要 beacon-to-beacon lock，约 1~10s 用示波器观察 MDI 上的 BEACON 波形
同 ID 导致双 coordinator 正常现象，最终会有一方胜出 只要最终有一方确立 coordinator 身份即可

六、实测结论与应用价值

6.1 三种模式的应用场景

模式 适用场景 能验证什么
单次/Burst 单 node 功能自测 TX 通路、lwIP、RAW MAC 回调功能正常
Burst 双 node CSMA/CD CSMA/CD 机制验证 carrier sense + backoff 工作正常（52ms wait 证据）
Burst 双 node PLCA 同 ID PHY collision detection 硬件验证 STS1.TXCOL + T1SPCSDIAG2.CORTXCNT 功能正常

6.2 核心结论

  1. PHY 层 collision detection 硬件始终正常工作：CDEN=1, STS1.TXCOL latch 正常, T1SPCSDIAG2.CORTXCNT 在无 collision 时正确保持 0

  2. CSMA/CD carrier sense 在多节点场景下正确工作：双 node burst 周期性 52ms 长 wait 证明总线竞争被成功推迟，这是正确的协议行为，不是测试失败

  3. 单 node vs 双 node 对比是 CSMA/CD 机制的最简验证方法：只需对比 wait time 分布，无需额外仪器，即可证明 carrier sense 在工作

  4. PLCA 同 ID 模式是唯一能确定性触发 wire-level collision 的软件方法：PLCA 的 TO 调度绕过了 carrier sense，两节点在同一 TO 内驱动 MDI → 必 collision
