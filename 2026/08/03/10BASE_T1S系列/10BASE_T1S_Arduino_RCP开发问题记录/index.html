Arduino IDE 编译问题记录：RCP 开发中的库路径与 include 问题

本文状态: 持续更新
库版本: Arduino_10BASE_T1S (src) + RCP 扩展
目标平台: Arduino UNO R4 Minima + LAN8650/LAN8651
记录日期: 2026-08-03

本文记录 RCP 开发过程中遇到的 Arduino IDE 编译问题及解决方案。

问题 1：RCP 头文件找不到（Arduino_10BASE_T1S_RCP.h: No such file or directory）

错误信息

原因分析

三层独立问题叠加：

第一层：库发现路径不匹配

Arduino IDE 的库扫描路径由 build.options.json 中的三个字段决定：

字段 路径
builtInLibrariesFolders C:\Users\cursorhu\AppData\Local\Arduino15\libraries
otherLibrariesFolders d:\1.Lumissil\10BASE-T\libraries
user C:\Users\cursorhu\Documents\Arduino\libraries

开发目录 Arduino_10BASE_T1S 的实际位置是 d:\1.Lumissil\10BASE-T\Arduino_10BASE_T1S，不在 otherLibrariesFolders 指向的 libraries 子目录下。IDE 在 d:\1.Lumissil\10BASE-T\libraries 里找不到 Arduino_10BASE_T1S，认为该库不存在。

第二层：sketch 缺少库锚点

Arduino IDE 的 libsdetect 机制依赖 sketch 中的 #include 来识别使用了哪些库。如果 sketch 直接 include <Arduino_10BASE_T1S_RCP.h> 而没有先 include <Arduino_10BASE_T1S.h>，IDE 的库扫描器无法将 Arduino_10BASE_T1S 库识别为依赖项，编译命令中就不会添加 -IC:\...\Arduino_10BASE_T1S 的路径。

第三层：RCP 头文件位置在库根而非 src/

Arduino_10BASE_T1S_RCP.h 位于库根目录（Arduino_10BASE_T1S/），而非标准 src/ 子目录。IDE 认为 src/ 是库的源码起点，即使库被正确识别，libsdetect 阶段也可能不包含库根目录作为 include 搜索路径。

解决方案

将 Arduino_10BASE_T1S_RCP.h 和 Arduino_10BASE_T1S_RCP.cpp 移动到 src/ 目录，与其他库源文件保持一致：

Step 4：重启 Arduino IDE

修改目录结构或 sketch include 后，必须完全关闭并重新打开 Arduino IDE，使 IDE 重新扫描库缓存。

预防措施

  1. 不要在库根放新的 .h/.cpp 文件：所有自定义源文件都放在 src/ 下
  2. 所有 sketch 必须包含 <Arduino_10BASE_T1S.h>：放在其他自定义 include 之前
  3. 在 sketchbook 下建立 libraries 目录：开发时将库放在 {sketchbook}/libraries/ 下，而非独立目录
  4. 修改目录结构后重启 IDE：Arduino IDE 会缓存库扫描结果

问题 2：Open1722 include 路径错误（No such file or directory）

错误 2.1：../Defines.h 在同级目录文件中

错误信息

原因分析

Utils.h 和 Defines.h 位于同一目录 src/Open1722/include/avtp/，不应使用 ../ 回到上级。只有子目录中的文件（如 acf/ 下的文件）才需要 ../ 来访问同级目录的成员。

修复

涉及文件：

  • src/Open1722/include/avtp/Utils.h：改为 #include "Defines.h" 和 #include "Byteorder.h"
  • src/Open1722/include/avtp/CommonHeader.h：改为 #include "Defines.h"

错误 2.2：.c 文件的 include 路径与实际目录结构不匹配

错误信息

原因分析

Open1722 的实际目录结构是：

编译命令中 include 路径为 -Id:\1.Lumissil\10BASE-T\libraries\Arduino_10BASE_T1S\src，这恰好是 src/Open1722/ 的父目录。因此：

  • 头文件 include/avtp/CommonHeader.h 需要用路径 Open1722/include/avtp/CommonHeader.h 访问
  • 用 Open1722/avtp/CommonHeader.h 会去 src/Open1722/avtp/（不存在）找文件

修复

所有 .c 文件中的 include 路径改为 Open1722/include/avtp/ 前缀：

涉及文件：

  • src/Open1722/src/avtp/CommonHeader.c
  • src/Open1722/src/avtp/Utils.c
  • src/Open1722/src/avtp/acf/Tscf.c
  • src/Open1722/src/avtp/acf/Ntscf.c

关键经验

定位 #include "xxx.h" 找不到时，先问自己：编译器的 include 搜索路径是什么？相对于哪个目录？

在本项目中：

  • 编译器的 -I 路径是 d:\1.Lumissil\10BASE-T\libraries\Arduino_10BASE_T1S\src
  • 所以 #include "Open1722/include/avtp/xxx.h" 展开为 d:\1.Lumissil\10BASE-T\libraries\Arduino_10BASE_T1S\src\Open1722\include\avtp\xxx.h，这正是头文件实际所在位置

问题 3：RCP API 调用错误（is not a member of 'rcp' / no matching function）

错误 3.1：RCP_EP_GPIO_BASE 被错误地放在 rcp:: 命名空间

错误信息

原因

RCP_EP_GPIO_BASE 定义在 RCP_Defs.h 中，属于全局命名空间（inline constexpr），但 sketch 中错误地加了 rcp:: 前缀。

修复

涉及文件：

  • examples/AVTP_NTSCF_Listener/AVTP_NTSCF_Listener.ino
  • examples/AVTP_NTSCF_Talker/AVTP_NTSCF_Talker.ino（clientWrite 调用）

错误 3.2：asServer 参数类型不匹配

错误信息

原因

asServer 的签名接受 rcp::RCP_Endpoint*（单个指针）+ uint8_t count，但 sketch 传入的是 rcp::RCP_Endpoint* [1]（数组）。

修复

错误 3.3：访问了私有成员 _transport

错误信息

原因

_transport 是 Arduino_10BASE_T1S_RCP 的私有成员，只有 _transport 下划线私有成员名。transport() 方法不存在。

修复

后续改进：添加 public 访问器

直接访问 _transport 破坏了封装性。更优的做法是在 Arduino_10BASE_T1S_RCP 中添加 public transport() 方法：

这样 sketch 中统一用 rcp.transport()->onAvtpFrame(...)，不依赖私有成员名。

预防措施

  1. 常量命名空间检查：所有 #include "RCP/RCP_Defs.h" 后出现的 RCP_EP_* 等常量默认在全局命名空间，只有类内枚举或显式 namespace rcp {} 包裹的才需要 rcp:: 前缀
  2. 函数签名一致性：调用 API 前先确认参数类型——单个对象指针 vs 数组指针 + 长度计数是不同的签名
  3. 封装性原则：私有成员（_ 前缀）不应在类外部直接访问，有公开需求时应提供 public 方法
